# Start Here

This is the doorway. The documents below can each be read on their own, but the first time through they are meant to be read in order — because the system is easier to understand as a *flow* than as a pile of separate rules. Read the core path once, top to bottom, and the whole machine falls into place. After that, come back to any single document as you need it.

The core path, at a glance:

[[Vault Overview]] → [[Vision and Usage Guide]] → [[System Rules]] → [[Property Schema Reference]] → [[Dashboard]] → [[Manifesto]]

## The Core Path

1. **[[Vault Overview]]** — the map. What the system is, and what the six layers are. Start here to see the shape of the whole before any detail.

2. **[[Vision and Usage Guide]]** — the flow in motion. How real material actually moves through the layers, day to day, from a first Source entry to an original Revolution note. This is where the pipeline stops being abstract and starts to make sense.

3. **[[System Rules]]** — the law. The exact mechanics: how each layer works, the phantom-link and activation rules, the controlled vocabularies, and the naming conventions. Read this once you have seen the flow and want the precise rules behind it.

4. **[[Property Schema Reference]]** — the dictionary. Every field on every note type, and what it holds. Skim it once, then treat it as something to consult, not to memorize.

5. **[[Dashboard]]** — the instrument. The single live page that shows the vault's open work across all layers. This is the view you will actually live in once notes start to accumulate.

6. **[[Manifesto]]** — the compass. The principles beneath all of it, in a form to return to when the system is doubted or drifted from. It reads best *last*, once you have seen the machine it describes.

That is the whole working system. If you read only these six, in this order, you know how to use the vault.

## When You Need Them

The remaining documents sit outside the core path. None is required; reach for each only when its moment comes.

- **[[Why It Exists]]** — the case for the whole system, addressed outward. Read it when you want the argument for why a vault built this way should exist, or when sharing the system with someone else.
- **[[The Layers as a Cosmos]]** — a philosophical reading of the layers as a mind and a small cosmos. Pure contemplation; skip it freely if it does not call to you.
- **[[Design Decisions]]** — the reasoning behind the architecture, the forks and why each was chosen. Read it when you want to know *why* something is built the way it is, or before changing it.
- **[[Team Collaboration]]** — an opt-in addendum for shared, multi-author use. Ignore it entirely if you work alone.

You do not have to read everything. Take the core path first; leave the rest passive until you need it. The vault itself works the same way.
